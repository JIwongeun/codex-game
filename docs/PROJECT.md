# 제품 및 게임 규칙

## 1. 제품 정의

`await CODEX: CONTEXT//OVERFLOW`는 AI 코딩 에이전트가 작업하는 동안 개발자가 90초 안에 즐길 수 있는 싱글플레이 웹 아케이드다.

`.io 게임`은 여기서 기술 방식이 아니라 다음 플레이 감각을 뜻한다.

- 링크를 열면 즉시 시작
- 한두 개 입력만 사용
- 짧은 판과 즉시 재도전
- 규칙은 단순하지만 점수 욕심으로 위험을 감수
- 서버 기능을 추가할 시간이 남으면 글로벌 점수로 비동기 경쟁

따라서 실시간 멀티플레이와 WebSocket 서버는 만들지 않는다.

## 2. 대상 플레이어

- Codex, 빌드, 테스트, 배포를 기다리는 개발자
- 짧은 휴식 동안 설치 없이 게임을 하고 싶은 심사위원과 일반 사용자
- Snake/Slither 계열 이동을 바로 이해하는 플레이어

개발자 농담을 모르더라도 이동, 수집, 위험, 점수 확정은 이해할 수 있어야 한다.

## 3. 핵심 경험

플레이어는 커서 형태의 캐릭터를 움직여 코드 토큰을 먹는다. 먹은 토큰은 꼬리가 되어 Context 사용량과 미확정 점수를 늘린다. 꼬리가 길수록 점수 배율과 위험이 커진다. 플레이어는 적절한 순간에 `COMPACT`하여 미확정 점수를 확정하고 주변 적을 제거한다.

핵심 감정은 다음 세 단계다.

1. 안전: 조금만 더 모을 수 있다.
2. 욕심: 지금 압축하면 아깝다.
3. 해소 또는 후회: 성공적으로 압축하거나 충돌로 미확정 점수를 잃는다.

## 4. MVP 게임 규칙

### 세션

- 한 판: 90초
- 시작 목숨: 3
- 첫 방문: 가입·로그인·닉네임 입력 없이 익명으로 바로 시작
- 입력: 마우스 이동 또는 방향키/WASD, `COMPACT`는 클릭 또는 Space
- 종료: 90초 경과 또는 목숨 소진
- 종료 후: 점수, 로컬 최고점, 즉시 재시작

### 이동

- 플레이어는 일정한 기본 속도로 계속 움직인다.
- 포인터 방향으로 부드럽게 회전한다.
- 키보드는 같은 이동 목표를 제공하는 대체 입력이다.
- 프레임률이 달라도 이동 거리와 타이머 결과가 같도록 delta time을 사용한다.

### 토큰과 Context

- 토큰을 먹으면 미확정 토큰 수와 꼬리 길이가 증가한다.
- 꼬리가 길어질수록 Context 게이지와 점수 배율이 증가한다.
- Context가 한계에 가까워지면 색, 화면 진동, 경고음으로 위험을 알린다.
- 최대치에 도달했을 때의 정확한 벌칙은 첫 graybox에서 재미를 비교한 뒤 결정한다.

### COMPACT

- 미확정 토큰을 확정 점수로 바꾼다.
- 꼬리를 안전한 기본 길이로 줄인다.
- 꼬리 길이에 비례한 원형 충격파로 주변 적을 제거하거나 밀어낸다.
- 짧은 꼬리로 반복 사용하는 것보다 오래 버틴 뒤 사용하는 편이 높은 점수를 줘야 한다.

### 충돌

- 적과 충돌하면 목숨 하나와 미확정 토큰을 잃고 짧은 무적 시간을 얻는다.
- 확정된 점수는 잃지 않는다.
- 자기 꼬리 충돌은 graybox에서 조작감과 난이도를 확인한 뒤 활성 여부를 결정한다.

### 적

MVP 적은 세 종류를 넘기지 않는다.

1. `TAB SWARM`: 작은 개체가 플레이어를 천천히 추적한다.
2. `MEMORY LEAK`: 일정 시간이 지나면 작은 개체로 분열한다.
3. `NOTIFICATION`: 예고 표시 후 직선으로 빠르게 돌진한다.

마지막 15초의 `DEADLINE` 연출은 core loop가 안정된 뒤 추가한다. 별도 보스 전투 시스템은 만들지 않는다.

## 5. 점수 원칙

정확한 수치는 플레이 테스트로 조정하되 구조는 다음을 유지한다.

```text
확정 점수 = 미확정 토큰 가치 × 현재 위험 배율
최종 점수 = 모든 확정 점수 + 생존 보너스
```

- 랭킹을 나중에 구현하더라도 확정 점수만 반영한다.
- 작은 COMPACT 반복보다 위험한 긴 꼬리가 유리해야 한다.
- 운보다 플레이어의 이동과 COMPACT 타이밍이 점수 차이를 만들어야 한다.

## 6. 화면과 피드백

- 논리 화면은 16:9, 1280×720이다.
- 플레이 영역을 가리는 DOM 패널을 만들지 않는다.
- 시작 시 조작법을 한 화면에 표시하고 첫 입력 후 사라지게 한다.
- 점수, Context, 배율, 목숨, 남은 시간은 항상 읽을 수 있어야 한다.
- 개발자 패러디는 피드백 문구와 가상의 프로세스 디자인에 사용하되, 충돌 판독을 방해하지 않는다.

## 7. MVP 포함 범위

- 시작, 플레이, 종료, 재시작 상태
- 마우스와 키보드 이동
- 토큰 생성, 수집, 꼬리 성장
- Context 게이지와 위험 배율
- COMPACT, 점수 확정, 충격파
- 적 최대 3종, 충돌, 목숨
- 90초 난이도 상승
- 로컬 최고점
- 음소거 가능한 기본 효과음
- 공개 production 빌드

## 8. MVP 제외 범위

- 실시간 다른 플레이어 또는 봇으로 위장한 플레이어
- 회원가입과 로그인
- 스킨, 상점, 재화, 업적
- 여러 맵과 게임 모드
- 복잡한 튜토리얼
- 실제 앱/브라우저 정보 접근
- 런타임 OpenAI API 기능
- 핵심 게임과 제출 준비가 끝나기 전의 서버, 게스트 ID, 글로벌 랭킹

## 9. 후순위 확장 기능

아래 기능은 핵심 게임, 공개 배포, QA, 제출 필수 자료가 모두 끝난 경우에만 구현한다.

- 자동 생성 게스트 ID와 표시명
- 게스트별 최고점 하나를 보여주는 글로벌 Top 10
- 점수 제출 실패 재시도

## 10. 재미 검증 기준

그래픽 고도화 전에 아래가 확인되어야 한다.

- 새 플레이어가 10초 안에 토큰을 먹고 COMPACT한다.
- 첫 판 후 점수 향상을 위해 한 번 이상 재시도하고 싶다.
- 길게 모으는 위험과 일찍 확정하는 안전 사이의 선택이 느껴진다.
- 사망 원인이 화면에서 이해된다.
- 60 FPS가 아닌 환경에서도 플레이 속도가 크게 달라지지 않는다.

두 명 이상에게 보여줄 수 있다면 설명 없이 플레이시키고, 막힌 지점만 기록한다.

## 11. 아직 열려 있는 게임 결정

- 자기 꼬리 충돌 활성 여부
- Context 최대 도달 시 즉시 피해 또는 짧은 Overflow 보너스 상태
- COMPACT 충격파가 적을 제거할지 밀어낼지
- 최종 15초 `DEADLINE`의 정확한 효과

이 항목은 graybox 플레이 후 `docs/DECISIONS.md`에서 확정한다.
